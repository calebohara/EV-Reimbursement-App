## CRITICAL

| # | File | Issue | Status |
|---|------|-------|--------|
| S1-1 | `js/summary.js:30-47` | Displayed totalKwh may not match the value used in totalCost calculation | FIXED |

### S1-1 Detail
- **Expected**: Summary chip shows the same totalKwh that was fed into `computeTieredTotals()` to produce the displayed totalCost
- **Actual**: `updateSummary()` independently recalculates totalKwh from DOM inputs (lines 30–39), counting only `value > 0` days. `computeTieredTotals()` (called at line 41) uses its own kwhMap. The displayed `#totalKwh` chip comes from the local calculation, not from `tierTotals.totalKwh`. A day with an explicit `0` entry may be counted differently between the two paths.
- **Fix**: Replace the locally-calculated `totalKwh` display at line 47 with `tierTotals.totalKwh` to guarantee displayed kWh matches the figure used to compute the dollar amount.

### S1-2 Detail
- **Expected**: Safe handling when `localStorage.key(i)` returns `null` (possible in multi-tab race conditions per MDN)
- **Actual**: `key.length` accessed without null guard; throws `TypeError` if key is null
- **Fix**: Add `if (!key) continue;` before `key.length` access in the loop

### S1-3 Detail
- **Expected**: Receipt PDF table rows should sum to the footer total, or the footer should only count rows shown
- **Actual**: Line 113 filters `if (kwh > 0)` to hide zero days from the table, but the footer at line 176 uses `totalKwh` which includes all days. A user can see that the sum of rows ≠ the total.
- **Fix**: Either remove the `kwh > 0` filter (show all days) or recompute totals from only the non-zero rows

### S1-4 Detail
- **Expected**: Left/right arrow keys navigate between stars; meets WCAG 2.1 SC 2.1.1 (Keyboard)
- **Actual**: Only Enter/Space work; arrow keys are unhandled on star elements
- **Fix**: Add `keydown` handlers for `ArrowLeft` / `ArrowRight` to move and select between stars

### S1-5 Detail
- **Expected**: `CACHE_NAME = 'ev-reimburse-v3.7.1'` to match every other version location
- **Actual**: `CACHE_NAME = 'ev-reimburse-v3.12.3'` — a 5-minor-version drift
- **Impact**: SW will force-refresh all users' caches unnecessarily on next deploy, and version shown in DevTools won't match the app version
- **Fix**: Align `sw.js` CACHE_NAME with current app version `3.7.1`

### S1-6 Detail
- **Expected**: Defensive null check before accessing `.classList` on `resultBox`
- **Actual**: `const resultBox = document.getElementById('resultBox')` at line 153 is not null-checked before `.classList.add('show')` at line 155. Element exists in current HTML, but this is a defensive gap.
- **Fix**: Add `if (!resultBox) return;` after line 153

### S1-7 Detail
- **Expected**: `v3.7.1` (full SemVer, matching other locations)
- **Actual**: Hardcoded string `'Generated by EV kWh Reimbursement App v3.7'` — missing patch version and not sourced from a shared constant
- **Fix**: Import APP_VERSION (same pattern as `feedback.js` and `stats.js`) and use `v${APP_VERSION}`

### S1-8 Detail
- **Expected**: Array should be cloned before sorting: `const sorted = [...history].sort(...)`
- **Actual**: `.sort()` called directly on the retrieved reference mutates the in-memory array; sorted order is not persisted to localStorage
- **Impact**: Low — sort order is cosmetic and re-applied on next render, but it's an unintended mutation

### S1-9 Detail
- **Expected**: Retrieved array cloned before mutation: `const profiles = [...storage.getProfiles()]; profiles.push(name);`
- **Actual**: Returned reference mutated before save; low risk in current sync code but bad defensive pattern
- **Fix**: Clone before push

### S1-10 Detail
- **Expected**: Consistent data type for empty-rate cells in both PDF and Excel exports
- **Actual**: `pdf.js:80` returns `0` (number) for zero-kWh days; `excel.js:54` returns `''` (empty string)
- **Impact**: PDF shows `$0.000` for zero days; Excel shows blank — confusing when reviewing tiered billing
- **Fix**: Standardize to `''` in both (blank is cleaner for zero-kWh rows)

### S1-11 Detail
- **Expected**: Each star button has `aria-pressed="true/false"` updated on selection, so screen readers announce "pressed" / "not pressed"
- **Actual**: Stars have `role="button"` but no `aria-pressed` attribute; selected state not announced to assistive technology
- **Fix**: Add `aria-pressed="false"` to each star in HTML; update to `"true"` on selection via JS in `feedback.js`

### S1-12 Detail
- **Expected**: `https://cdn.jsdelivr.net/npm/chart.js@4.4.0` (or pinned version) for deterministic behavior
- **Actual**: `https://cdn.jsdelivr.net/npm/chart.js` — unpinned; SRI hash prevents tampering but doesn't prevent silent behavior changes if the CDN resolves to a new major version
- **Fix**: Pin to a specific version (e.g., `@4.4.0`) and update SRI hash accordingly

## Notes / Intentional Patterns

- **Email hardcoding** (`js/feedback.js` + `index.html:424`): `caleb.ohara@siemens.com` is hardcoded as the feedback recipient. This is intentional by design but represents a spam/privacy exposure. Not filed as a bug — document as a known tradeoff.
- **`innerHTML` in feedback.js**: Used only for button icon state restoration (hardcoded Bootstrap icon HTML, not user data). Not a security vulnerability.
- **Profile deletion guard**: Default profile is protected — `profiles.js:61-64` prevents deleting the last profile. ✓
- **All CDN resources**: SRI hashes present on all other CDN deps (Bootstrap, SheetJS, jsPDF). Only Chart.js lacks version pinning (S1-12).
- **`URL.revokeObjectURL`**: Properly called in `csv.js:58` after blob download. ✓
- **APP_SHELL_RELATIVE**: All 15 JS files + 6 CSS files accounted for in `sw.js`. ✓
